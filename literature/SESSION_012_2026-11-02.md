## 1. Methodological correction: complete finite-state search

The previous Session 011 lasso enumeration on the flexible three-state actuator was bounded. In this session we implemented a **complete** finite-product-graph algorithm in `src/exhaustive_offset_audit.py` with nine negative-control tests in `tests/test_exhaustive_offset_audit.py`.

For two formulas `G(a -> X^k b)` and `G(a -> X^m b)`, where `a` means physical state 0 and `b` means state 2, the algorithm:

1. Starts at physical state 0 and tracks a suffix of at most `max(k,m)+1` physical states.
2. Excludes every transition that violates the formula required to stay true.
3. Records whether the formula required to be false has already been violated.
4. Explores the entire reachable finite product graph, then searches for a reachable directed cycle **after** the desired violation.
5. Converts the path and cycle into an infinite ultimately periodic physical trace, checking every physical edge including loop closure and independently rechecking both temporal formulas.
6. Raises `SearchBudgetExceeded` if the node budget is hit; **resource exhaustion is not reported as equivalence**.

**Why this is complete on the declared finite model:** any infinite path that forever satisfies one bounded-next safety formula and eventually violates the other must reach a state with the violation flag set and then visit a product vertex twice, giving a cycle. Conversely, a reachable cycle after violation yields an infinite admissible lasso satisfying the required formula and violating the other. This is an elementary, established finite-state model-checking construction, **not a new theorem or algorithm**.
