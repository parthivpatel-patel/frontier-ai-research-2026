# Protocol 028 — Native scientific figure provenance and falsification

Date: 2026-11-02 (US Eastern). Status: preregistered design only; **no new experiment or figure has been executed under this protocol**.

## Research question

Can the existing bounded LTL checker produce an independently reproducible, example-level visualization that demonstrates the precise effect of a declared proposition-identity assumption without exposing restricted external benchmark text? This is a methodological visualization and audit, **not** evidence of improved AI semantic accuracy or a new model-checking algorithm.

## Frozen constructed example

Compare `G prop_0` with `G prop_1`. Run the existing bounded infinite-lasso checker with `max_states=3`, `max_propositions=2`, `max_cases=20000` under (A) no equality and (B) `equalities=(("prop_0","prop_1"),)`. Both formulas and valuations are **synthetic constructed fixtures**, not external model predictions or physically validated propositions.

Expected logical outcome, subject to independently executed confirmation: under (A), a valuation with `prop_0=true` and `prop_1=false` at the only state of a one-state lasso makes the formulas disagree; under (B), they cannot disagree on any valuation satisfying the equality, so the bounded checker returns no witness. No-witness-within-bound must never be labeled a general proof of equivalence. The equality is an *assumption*, not a measured physical fact.

## Figure artifact requirements

1. The figure must be generated by Python code checked into this repository, run by the public standard GitHub Actions runner. Do not use an image-generation model or manually draw result graphics.
2. Export an unmodified, programmatically plotted PNG and its underlying machine-readable JSON, together with SHA-256 hashes, source commit, Python version, UTC execution time, exact command, protocol identifier and explicit `constructed example` label.
3. Display proposition truth values on each lasso state, loop-back arrow, satisfaction of each formula at the initial state, and the equality condition in both panels. The program must compute formula satisfaction with the repository evaluator, not manually assign outcome labels.
4. Assert the exact reported witness status and reproduce the JSON/PNG from a clean checkout. Test that an intentionally changed equality constraint changes the expected result; fail CI if the trace and checker disagree.
5. Provide an accessible figure caption: 'Constructed bounded LTL counterexample; illustrates assumption sensitivity, not external AI model performance or validated physical dynamics.'
6. Never mix constructed witness visualizations with the external 500-record aggregate audit or imply that the constructed example is one of the nine observed external witnesses. For the external audit, only publish aggregate counts that have been independently verified in the existing cloud logs.
7. Restrict execution to free standard public-repository runners, bounded runtime and standard Python dependencies. No GPU, paid service, local laptop compute or card requirement.

## Failure and stopping criteria

If the checker cannot return or independently reconstruct the exact witness valuation, the native figure is **blocked** until an opt-in, constructed-fixture-only witness API is implemented and regression-tested. Do not reverse engineer an example from aggregate counts. If the output disagrees with a second independent evaluator or the provenance hash is absent, do not publish the figure as a scientific result. If source permissions prohibit reproducing external predictions, use only the constructed example and clearly identify it as such.

## Novelty and publication gate

Bounded LTL model checking and counterexample traces are established techniques; this protocol does not establish novelty. The primary proposed scientific hypothesis remains whether calibrated, independently validated physical-predicate uncertainty reduces unsafe acceptance at matched coverage relative to strong semantic-verification and abstention baselines. A publishable claim requires permitted data, blinded human adjudication, independent baselines, uncertainty intervals and a predeclared falsification threshold. Negative findings remain reportable. Disclosure of AI assistance must follow venue requirements.
